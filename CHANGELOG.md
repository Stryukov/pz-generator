# Changelog

Все заметные изменения артефактов проекта. Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/).
Версии фиксируются тегами git. Правки вносятся в раздел [Unreleased]; при достижении вехи
он переименовывается в версию с датой, ставится тег, заводится новый [Unreleased].

## [Unreleased]
### Added
- **Маршрутизация типов расчёта** (`templates/types.json` + узлы `Fetch Types` / `Detect Type` /
  `Fetch Columns`). Тип определяется **до извлечения** по маркерам (имя файла, `calc_type`,
  подстроки текста), после чего карта колонок, спека и шаблон качаются по **динамическим URL**.
  Таблица типов лежит в репозитории → **добавление нового типа = запись в JSON + файлы, без
  правок флоу** (конвенция «флоу статичен»). Предикаты: `calc_type`, `filename_contains`,
  `text_all`, `text_any`, `text_none`; первое совпадение выигрывает, иначе `default`.
- `docs/01` разделён: общая часть контракта + карты колонок по типам
  (`01-columns-format-A.md`, `01-columns-prochie-on.md`). Агент извлечения получает **одну**
  карту вместо всех — меньше шансов перепутать формат, и `docs/01` перестаёт расти с каждым
  новым типом.
- **Подтверждение типа**: манифест получил поле `doc_type` (агент проставляет его по заголовку
  полученной карты), оба `Validate` сверяют его с типом от детекции и отдельно ловят
  `doc_type_matched=false` (ни одно правило не сработало → применён `default`). Ошибка
  маршрутизации всплывает **до генерации**, а не в готовой записке.

### Changed
- Порядок узлов: конверсия расчёта (`Calc Type? → … → Calc Text`) поднята **выше** Fetch-узлов —
  без текста расчёта тип определить нельзя. `Load Contracts` теперь склеивает
  `extraction_system` = общая часть + карта колонок + схема.
- **Правило НДС переписано** (`docs/01` §«НДС»): жёсткое «тариф без НДС» заменено на определение
  **из расчёта**. Для ФЛ (население) НДС уже в тарифе, для ЮЛ — сверху. Главный признак —
  строка нумерации колонок: формула с `×1,2` (`12=6*4*1,2`) → тариф без НДС; без множителя
  (`18=13*7`) → тариф уже с НДС. Заголовок «руб. с НДС» относится к сумме, не к тарифу, и для
  определения конвенции непригоден. Проверено численно на Прочих ОН и на УК.
- Карта «формата B» переименована в **Прочие ОН** и обновлена под стандартизованный образец
  (`1139 ОБРАЗЕЦ`): колонка «Дата, № счет-фактуры»; правило игнорировать подколонку
  «по прибору учета» у стоков ГВС (её скрывают — стоки по прибору практически не считают);
  явное указание, что нулевой ХВС при ненулевых стоках — **не** сторно; «Корректировка долга»
  в записку не выводится.

### Fixed
- xlsx-ветка: биллинговые выгрузки имеют **сломанный `<dimension>`** (заявляет меньше строк, чем
  есть) → n8n `Extract from File`/SheetJS читал только 2 месяца из 13. Заменено на конвертацию
  **xlsx2csv** через Execute Command (`Write Calc XLSX → XLSX to CSV → Cleanup XLSX`), которая
  читает реальные строки. Требует `python3` + `pip install xlsx2csv` в контейнере.
- Валидатор (`Validate`/`Validate 2` + `docs/03`): null-guard тарифного интервала —
  не падать `schema:…null…slice` при `date_to: null` (открытый интервал трактуется как «до конца»).
- Верификация сборки: все Code-узлы прогоняются через `node --check` (ловит реальный LF внутри
  JS-литералов — прежний класс ошибок).

### Added
- **Фоллбэк реквизитов из расчёта, когда доп-контекст пуст** (`docs/01` §2 и §4, `docs/02`):
  явная цепочка источников **доп-контекст → расчёт → плейсхолдер** (приведена в соответствие с
  `source_priority` шаблона, который её объявлял с самого начала). Конкретно: (1) `pu_list` —
  нет данных ПУ, но есть колонка «Объект …, адрес» → запись на каждый уникальный адрес с
  `meter_no`/`poverka_date` = `null`; (2) `executor_context.objects` — нет таблицы объектов в
  доп-контексте → те же адреса с `purpose = null`; (3) `executor_context.ispolnitel` — нет в
  доп-контексте → из блока подписи «Исполнитель:» под таблицей расчёта (должность + ФИО, без
  телефона и даты). `normativ_npa`/`nvcs_mode_override` фоллбэка не получают — в расчёте
  источника нет. Разобрано на расчёте Жилремстроя (многообъектный ОДН).
- `templates/document-template-type-A.json`: плейсхолдер **`meter_no`** (`<№ прибора учёта>`) —
  раньше отсутствовал, пустой колонке таблицы ПУ нечем было рендериться.
- `docs/05`: **агрегация однотипных пропусков** — повторяющийся по строкам `pu_list` пропуск
  даёт один комментарий исполнителю, а не по одному на строку (на 30 объектах было бы ~60).
- Приём расчёта в **xlsx**: `Prepare Inputs` принимает PDF и xlsx (`calc_type`), приоритет
  выбора — код биллинг-выгрузки `dbt_rep_ul_nach_pay` или «расчёт задолженности»; развилка
  `Calc Type?`: pdf → pdftotext (как раньше), xlsx → `Extract XLSX` + `XLSX to Text`
  (;-разделённый текст); обе ветки сходятся в `Calc Text`.
- `docs/01`: карта колонок **формата B** (xlsx-выгрузка `V_RP_PKV_DBT_REP_UL_NACH_PAY`):
  реквизиты из шапки, объёмы по ПУ/нормативу/итого, суммы уже с НДС, служебные строки
  «Итого за месяц»/«Всего:», сторно-месяцы → нули + note; НВЦС/п.203 отсутствуют.
- `docs/02`: опциональное `months[].note`; `docs/05`: все `months[].note` — в комментарии
  исполнителю, в текст записки не выводятся.
### Added
- `templates/reference-type-A.docx` — reference-документ pandoc: формат ПЗ (Times New Roman 14,
  выравнивание по ширине, поля 2/1,5/2/3 см), плейсхолдеры — красный `Verbatim Char`.
### Changed

- `docs/01`: **арифметическая самопроверка** извлечения (с НДС ≈ без НДС × 1,2; month_total =

- Блок 2 (назначение) — поддержка **нескольких объектов**: в манифесте `executor_context.objects`

  доп-контекста; генерация выводит отдельным удаляемым абзацем «На объекте по адресу: … располагается

- `executor-context.md`: объекты/назначение вынесены в отдельную таблицу; убран «Режим НВЦС»

- Плейсхолдеры в записке — угловые скобки `<…>`, оформленные **цветным кодом**
  (`<code class="ph" style="color:#c0392b">&lt;…&gt;</code>`) вместо маркера «‹…›». Обновлены

## [0.1.0-beta] - 2026-07-16
### Added
- Спецификация записки (структура, вариации, источники) — Тип А.
- JSON-шаблон сборки (флаги, дословные болванки) — Тип А.
- Мини-шаблон доп-контекста для исполнителя.
- Каркас репозитория, README, заглушки контракта и флоу.
- Контракт на результат для генерирующего агента (docs/02-contract.md).
- Флоу: зафиксирована петля повторного извлечения и статусы полей (ok/assumption/missing).
- Документ извлечения и валидации: схема манифеста, контракт агента извлечения, правила валидации (пример-месяц + итоги).

- n8n workflow (импортируемый JSON) + инструкция; контракты подгружаются из репозитория, флоу статичен.

### Changed
- Флоу: извлечение текста расчёта переведено с `Extract from File` (pdf-parse ломал кириллицу
  в шрифтах Type0/CID) на **poppler `pdftotext -layout`** (узлы `Write Calc PDF` + `PDF to Text`
  через Execute Command; `Cleanup PDF` удаляет temp-файл). Заголовки колонок теперь читаемы.
- docs/01: добавлена **карта колонок по заголовкам** (устойчива к отсутствию групп НВЦС/п.203
  и к разному числу тарифных интервалов).
- Бета: в генерацию подгружается `templates/document-template-type-A.json` (узел
  `Fetch Template`) — модель получает дословные болванки и шаблоны блоков, а не пересказ.
- Бета: контракт извлечения (`docs/01`) + схема (`docs/02`) — помесячные суммы берутся
  **с НДС** (итоговые колонки); `month_total` = ИТОГ месяца (не колонка п.203);
  `sum_p203` из колонки п.203; `V_stoki` читается из расчёта отдельно (может ≠ `V_hvs`);
  извлекаются **все тарифные интервалы**. Разобрано на реальном расчёте Степанова.
- Бета: валидация (`docs/03` + узлы Validate) — убрана ошибочная проверка `V_stoki=V_hvs`;
  п.203 проверяется только на наличие суммы (формула уточняется у эксперта); добавлены
  schema-гварды (`schema:*`) вместо JS-краша при неполном манифесте.
- Флоу переведён на локальную модель: три агента (извлечение/повтор/генерация) — узлы
  `Basic LLM Chain` + под-узел `Gemma (Ollama)` вместо HTTP-запросов к Anthropic; модель
  задаётся жёстко в узле, из `Config` убраны `model` и `anthropic_version`.
- Флоу: расчёт подаётся модели текстом через новый узел `Extract Calc Text`
  (`Extract from File`), а не PDF-документом base64 (Gemma — текстовая модель).
- Флоу: контракты грузятся четырьмя `HTTP Request`-узлами (`Fetch Extraction/Schema/Spec/
  Generation`), `Load Contracts` только склеивает строки. Причина: `helpers.httpRequest`
  внутри Code-узла виснет в task-runner n8n (таймаут задачи 60 с).
- Флоу: на `Fetch *`-узлах включён Retry On Fail (транзиентный ECONNRESET от GitHub raw).
- Флоу: узел `Gemma (Ollama)` — модель `gemma3:27b`, `temperature 0`, `numCtx 16384`,
  `keepAlive 30m` (numCtx критичен: при дефолтных 2048 длинный системный промпт обрезался).
- Флоу: исправлена отправка ответа — `from` берётся как адрес (`from.value[0].address`),
  `from/subject/messageId` в `Parse Output` тянутся из `Parse Manifest`; вложение `zapiska`
  перенесено в `options.attachments`; в тексте писем реальные переводы строк;
  `appendAttribution: false`.
- Флоу: из `Filter Subject` убрана проверка отправителя (защита от петли не нужна в топологии
  отдельного ящика ПЗ); `Prepare Inputs` кладёт выбранный расчёт под ключ `calc`.
- Флоу: узел `Prepare Inputs` — устойчивый разбор вложений (отбор PDF-расчёта по имени файла
  вместо «первого PDF» — исключаются пени/поручение/пояснительная/реестр).
- Репозиторий: удалён дубликат воркфлоу `n8n/pz-avtomat.workflow.json` (артефакт
  переименования проекта); `examples/` вынесены в `.gitignore` (реальные клиентские файлы).
- n8n/README: для self-hosted рекомендован Gotenberg как конвертер HTML→DOCX.
- Проект переименован в pz-generator; во флоу прописан docs_base_url репозитория (ветка main).
- Именование: латинское `tip` → `type`; файл исполнителя → `executor-context.md`.
- Документы разделены по этапам пайплайна и перенумерованы (00-flow, 01-extraction-contract, 02-manifest-schema, 03-validation-rules, 04-spec, 05-generation-contract).
- Контракты извлечения и генерации приведены к строгой форме (Задача/Контекст + Формат/Обязательное/Запреты/Детализация/Готово когда).
- В правила валидации добавлен референс-код для n8n Function-node.

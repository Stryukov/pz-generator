# Схема манифеста

**Манифест** — структурированный JSON по одному делу: числа, флаги, реквизиты, извлечённые
из расчёта и доп-контекста. Общий артефакт стыка: **производится** извлечением (шаг 2),
**потребляется** валидацией (шаг 3) и генерацией (шаг 4).

Отличать от **шаблона** (`templates/document-template-type-A.json`) — тот общий на все
записки (болванки, порядок блоков) и от дела не зависит.

Принцип: манифест хранит **сырые числа** (`11273.59`), не форматированные строки.
Оформление («11 273,59 руб.») — задача генератора.

```jsonc
{
  "doc_type": "prochie-on",          // тип расчёта — из заголовка полученной карты колонок
                                     // ("format-A" | "prochie-on" | …). Сверяется валидацией
                                     // с типом, определённым до извлечения.
  "abonent": {
    "name": "ИП Чебанова Виктория Владимировна",   // null если не найдено
    "contract_no": null,
    "contract_date": null,
    "address": "г. Вилючинск, ул. Строительная, д.6"
  },
  "flags": {
    "calc_method": "pu",            // "pu" | "norm"
    "is_recalc": true,              // повторный расчёт в связи с поверкой
    "has_nvcs": true,
    "nvcs_mode": "p123_4",          // "p123_4" (по умолчанию) | "razdel_13"
    "k_coefficient": 0.5,           // = sum_nvcs / sum_stoki
    "has_p203": true,
    "has_gvs": false,
    "has_seasonality": false,
    "sewage_percent": 20.4          // преобладающий процент канализирования =
                                    // объём стоков ХВС / объём ХВС (стоки ГВС в базу НЕ входят!).
                                    // 100 или null — стоки равны потреблению, пояснение не выводится.
                                    // Месяцы с иным процентом — в issues (комментарий исполнителю)
  },
  "pu_list": [                      // если calc_method = "pu"
    { "object": "кафе Пит-Стоп", "meter_no": "580873119", "poverka_date": null }
    // если в расчёте только адреса объектов (без приборов): object = адрес,
    // meter_no и poverka_date = null → в записке плейсхолдеры
  ],
  "normativ": {                     // если calc_method = "norm"; иначе null
    "npa": null, "volume_hvs": null, "volume_gvs": null
  },
  "tariffs": [
    { "date_from": "2025-01-01", "date_to": "2025-06-30",
      "tariff_hvs": 55.89, "tariff_vo": 94.25, "nds": "without" },   // "with" | "without"
    { "date_from": "2025-07-01", "date_to": "2025-12-31",
      "tariff_hvs": 163.13, "tariff_vo": 207.50, "nds": "without" }
  ],
  "tariff_npa": "Постановление РСТ Камчатского края № 33-Н от 05.03.2025",
  "months": [                       // суммы sum_* и month_total — С НДС (итоговые колонки расчёта)
    { "month": "2025-04",
      "V_hvs": 168.092, "sum_hvs": 11273.59,
      "V_gvs": 0, "V_stoki": 168.092, "sum_stoki": 19011.20,
      "sum_nvcs": 9505.61, "sum_p203": 38022.41,
      "month_total": 77812.81,
      "calc_basis": "pu",           // "pu" | "norm" | "average" — основание расчёта месяца.
                                    // "average" (по среднему) из расчёта НЕ виден — ставится
                                    // только если исполнитель указал месяц в доп-контексте
      "sewage_percent": 20.4,       // процент этого месяца: стоки ХВС / ХВС; null при V_hvs = 0
                                    // (месяцы с null своей группы примеров НЕ образуют)
      "has_adjustment": false }     // в колонке оплаты вместо суммы стоит пометка о корректировке
    // ... остальные месяцы; опционально "note": "перерасчёт/сторно — проверьте"
    //     (пометка извлечения о нетипичном месяце; генерация выносит её в комментарии исполнителю)
  ],
  "example_month": "2025-04",       // основной репрезентативный месяц (его проверяет валидация)
  "example_months": ["2025-04"],    // все месяцы-примеры: по одному на каждый различающийся
                                    // вариант расчёта (пара calc_basis + sewage_percent).
                                    // Первый элемент совпадает с example_month
  "totals": { "charged": 275509.30, "paid": 0, "balance": 275509.30 },
  "executor_context": {
    "ispolnitel": null,             // "ФИО, должность" — из доп-контекста; нет → из блока «Исполнитель:» расчёта
    "objects": [                    // объекты из доп-контекста; нет → адреса из расчёта (purpose = null);
      { "address": null, "purpose": null }   // [] — нет; "DELETE" в purpose → удалить блок
    ],
    "normativ_npa": null,           // только доп-контекст (в расчёте источника нет)
    "nvcs_mode_override": null,     // только доп-контекст
    "contract_date": null,          // дата договора для договорного абзаца
    "average_months": [],           // месяцы, посчитанные по среднему: [{month, reason}].
                                    // Из расчёта не видно — только со слов исполнителя
    "adjustment": null,             // пояснение к корректировке долга (см. docs/05):
                                    // { period, amount, reason } — чего нет, то плейсхолдер
    "sewage_reason": null,          // придаточный оборот: почему стоки не равны потреблению.
                                    // ТОЛЬКО из доп-контекста, дословно — из расчёта причина
                                    // не видна; нет → null + плейсхолдер в записке
    "expand_all_months": false      // исполнитель явно попросил расписать каждый месяц
  },
  "issues": {
    "missing": ["abonent.contract_no", "executor_context.ispolnitel"],
    "assumption": []                // заполняется валидацией
  }
}
```

## Статусы полей
- Поле не найдено ни в расчёте, ни в доп-контексте → `null` + запись в `issues.missing`.
- Поле не прошло валидацию после повтора → запись в `issues.assumption` (значение остаётся
  как есть, добавляется текст расхождения).
- Поле не в списках `issues` = `ok`.

Генератор читает `issues` и действует по контракту генерации: `missing` → плейсхолдер;
`assumption` → значение как есть + комментарий исполнителю.

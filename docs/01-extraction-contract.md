# Контракт на результат — извлечение данных (шаг 2)

Инструкция для **агента извлечения**.
Вход: контракт (этот файл) + схема манифеста (`docs/02-manifest-schema.md`) + расчёт (PDF;
в будущем xlsx) + доп-контекст исполнителя (тело письма/вложение).
Выход: манифест — JSON строго по схеме.

## Задача
Прочитать расчёт и доп-контекст и вернуть манифест: числа, флаги, реквизиты по делу.
Не пересчитывать, не форматировать, не додумывать — только точное извлечение.

## Контекст
- Данные пойдут в судебный документ — цена ошибки высокая.
- Расчёт — плотная таблица (много колонок по месяцам); часть полей может отсутствовать.
- Числа далее сверяются валидацией; при расхождении извлечение запускается повторно с
  обратной связью.

---

## 1. Формат
- Строго JSON по схеме `02-manifest-schema.md`. Без текста, пояснений и Markdown вокруг.
- Числа — сырые, разделитель дробной части — точка (`11273.59`). Никаких пробелов, запятых,
  «руб.», «м³».
- Даты — `YYYY-MM-DD`; месяцы — `YYYY-MM`.

## 2. Обязательное
- Флаги выводятся **из расчёта**:
  - `has_nvcs`, `has_p203`, `has_gvs` = true, если в расчёте есть соответствующая сумма/колонка.
  - `k_coefficient = sum_nvcs / sum_stoki` (округлить до 0,5 или 2,5, если попадает в допуск).
  - `has_seasonality` = true, если объём стоков ГВС меняется по месяцам (есть/ноль).
  - `is_recalc` = true при признаке повторного расчёта в связи с поверкой.
- `nvcs_mode` = `p123_4` по умолчанию; `razdel_13` — только если задано в доп-контексте.
- Извлечь **все** месяцы периода в `months[]`.
- **Суммы — итоговые с НДС**: у начисления в расчёте три колонки (без НДС / НДС / с НДС) —
  в манифест идёт колонка **с НДС** (`sum_hvs`, `sum_stoki`, `sum_nvcs`, `sum_p203`, `month_total`).
- Извлечь **все тарифные интервалы** в `tariffs[]` — тариф может меняться внутри периода
  (напр. до 30.06 и с 01.07).
- Выбрать `example_month`: первый месяц; если он нулевой/частичный/нетипичный — ближайший
  типичный (и это должно быть видно валидации/исполнителю).
- Ненайденное поле → `null` + путь поля в `issues.missing`.
- **Приоритет источников: доп-контекст → расчёт → `null` + `issues.missing`.** Если поле есть в
  обоих — доп-контекст **переопределяет** расчёт (исполнитель знает контекст дела). Конкретно:
  - `ispolnitel`, `objects` (адрес+назначение) — есть в доп-контексте → оттуда; нет → **фоллбэк
    на расчёт** (правила в §4); нет нигде → `null` + `missing`;
  - `normativ_npa`, `nvcs_mode_override` — **только** доп-контекст (в расчёте источника нет):
    не заполнено → `null` + `missing`, фоллбэка нет.
- В таблицах доп-контекста источник данных — **только столбец «Ваше значение»**. Столбец
  «Пример заполнения» (и любые примеры в шаблоне) **игнорировать полностью**: пример — не данные.
  Пустое «Ваше значение» → поле отсутствует (`null` + `issues.missing`).

## 3. Запреты
- Не выдумывать и не «додумывать» числа, даты, реквизиты, НПА. Нет данных → `null`.
- Не пересчитывать и не «исправлять» суммы — извлекать как в расчёте (пересчёт делает валидация).
- Не форматировать числа (никаких `11 273,59`, только `11273.59`).
- Не интерпретировать юридический режим за пределами правила `nvcs_mode`.
- Не заполнять `issues.assumption` — это делает валидация.

## Карта колонок расчёта (ориентир по заголовкам, НЕ по позициям)
Известны **два формата** расчёта — различать по заголовкам. Колонки определять **по заголовкам**,
не по номеру/порядку: состав колонок меняется от абонента к абоненту (НВЦС и п.203 могут
отсутствовать, тарифных интервалов 1–3).

### Формат A — широкий PDF (тройки «без НДС / НДС / с НДС»)

- Каждое начисление — группа из трёх колонок: **[без НДС] [НДС 20%] [итог с НДС]**. В манифест
  идёт **итог с НДС** (заголовок вида «Всего начислено … с НДС»).
- `V_hvs` — «начислено по ПУ, м³» (объём ХВС); `V_stoki` — «Стоки, м³» (объём водоотведения);
  `month_total` — «Всего начислено по счёту» (крайняя правая итоговая колонка строки).
- Группа **НВЦС** («плата за негативное воздействие на централизованную систему
  водоотведения») есть **не всегда**: есть группа → `has_nvcs=true`, `sum_nvcs` = её «итог с НДС»;
  нет группы → `has_nvcs=false`, поле не выдумывать.
- Группа **п.203** («плата за сброс загрязняющих веществ») — аналогично и **независимо** от
  НВЦС → `has_p203` + `sum_p203`.
- Внизу таблицы: «Итого» → `totals.charged`, «Оплачено» → `paid`, «Остаток долга» → `balance`.
### Формат B — xlsx-выгрузка биллинга (`V_RP_PKV_DBT_REP_UL_NACH_PAY-N.xlsx`)
Текст приходит `;`-разделённым (по строке на ряд таблицы), шапка трёхуровневая + строка с
нумерацией колонок 1–23.
- **Реквизиты — в шапке над таблицей**: название расчёта; строка «[абонент], договор № […]»
  → `abonent.name`, `contract_no`; строка «за период: …».
- Колонки: «Объект …, адрес» (→ `abonent.address`; объектов может быть несколько);
  «Период задолженности» (месяц); «Тариф, руб/м3» ХВС и стоков; объёмы ХВС
  **по прибору учёта / по нормативу / Итого** (→ `V_hvs` = Итого; метод: есть значения
  «по ПУ» → `calc_method="pu"`); объёмы стоков ХВС/ГВС/Итого (→ `V_stoki`, `V_gvs`);
  «Сумма к оплате за ХВС (руб. с НДС)» по ПУ/нормативу/**Итого** (→ `sum_hvs` = Итого);
  суммы стоков ХВС/ГВС/Всего (руб. с НДС) (→ `sum_stoki`); «Всего к оплате (руб. с НДС)»
  (→ `month_total`); «Оплачено»; «Остаток задолженности».
- **Суммы уже с НДС** (заголовки это указывают) — брать колонки «Итого/Всего» как есть.
  Тариф — без НДС: самопроверка `сумма ≈ V × тариф × 1,2` действует.
- Строки «Итого за [месяц]» и «Всего: объем/оплата/долг» — **служебные**, в `months[]`
  не включать. «Всего: оплата» → `totals.paid`; «Всего: долг» → `totals.balance`;
  `totals.charged` = сумма `month_total` (сверить с оплатой+долгом).
- **Сторно-месяц**: начисление по ПУ и равное отрицательное снятие по нормативу (итог месяца
  пуст/0) → в `months[]` все объёмы и суммы = 0, `note` = «перерасчёт/сторно — проверьте».
- НВЦС/п.203-колонок в формате B нет → `has_nvcs=false`, `has_p203=false`.

- **Арифметическая самопроверка (обязательно, заголовки бывают неоднозначны):**
  - сумма **с НДС** ≈ (сумма без НДС) × 1,2. Если извлечённая сумма ≈ V × тариф (без ×1,2) —
    ты взял колонку **БЕЗ НДС**: возьми следующую итоговую колонку «с НДС»;
  - `month_total` («Всего начислено по счёту») должен равняться **сумме извлечённых строк**
    (ХВС + стоки [+ НВЦС] [+ п.203], все с НДС). Не сходится → строки взяты не из тех колонок —
    перечитай тройки колонок заново;
  - `totals.charged` должен равняться сумме `month_total` всех месяцев.

## 4. Детализация
- **Суммы — с НДС** (см. §2): `sum_hvs`, `sum_stoki`, `sum_nvcs`, `sum_p203`, `month_total` —
  из **итоговой колонки с НДС**, не «без НДС».
- `month_total` — **итоговая сумма за месяц с НДС** (последняя итоговая колонка строки),
  НЕ колонка п.203 и не промежуточный итог.
- `sum_p203` — из **колонки п.203** (с НДС); `has_p203=true` только если такая колонка есть.
- `V_stoki` — из колонки **водоотведения** расчёта; **может отличаться** от `V_hvs`
  (объём стоков задаётся отдельно). `V_gvs` — только при `has_gvs`.
- `tariffs`: по каждому интервалу — `date_from`/`date_to`, `tariff_hvs`, `tariff_vo`, `nds`
  (`with` / `without` — ровно как в расчёте). Интервалов может быть несколько.
- `pu_list`: по одной записи на прибор (объект, номер, дата поверки; нет даты → `null`).
  **Фоллбэк на адреса:** нет данных ПУ, но в расчёте есть колонка с адресами объектов
  («Объект водопотребления и водоотведения, адрес») → заполнить по одной записи на
  **уникальный** адрес: `{ "object": "<адрес>", "meter_no": null, "poverka_date": null }`.
  Порядок — как в расчёте; адреса дедуплицировать (в xlsx-выгрузках адрес повторяется в
  каждом месяце). `[]` — только если в расчёте нет ни ПУ, ни адресов.
- `executor_context.objects`: список `{address, purpose}` из доп-контекста (таблица объектов).
  `purpose = null`, если назначение не указано. Пустой список или `"DELETE"` в `purpose` — если
  исполнитель просил удалить блок назначения.
  **Фоллбэк:** нет таблицы объектов в доп-контексте → взять те же уникальные адреса из расчёта,
  `purpose = null` (назначения в расчёте нет — оно станет плейсхолдером).
- `executor_context.ispolnitel`: строка `"ФИО, должность"`. Нет в доп-контексте → **фоллбэк на
  расчёт**: под таблицей бывает блок подписи — строка «Исполнитель:», далее **должность** и
  **ФИО** отдельными строками. Собрать как `"ФИО, должность"`
  (напр. `"Докучаева Е.А., Ст. специалист по работе с ЮЛ ЕРЦ"`). **Отбросить** телефон
  (`тел. …`) и строку с датой/подчёркиванием подписи. Блока нет → `null` + `missing`.
- `totals`: `charged`, `paid`, `balance` — из строк «Итого / Оплачено / Остаток» расчёта.

## 5. Готово когда
- Манифест валиден по схеме, все обязательные секции присутствуют.
- Все ненайденные поля перечислены в `issues.missing`; выдуманных значений нет.
- Флаги согласованы с числами: если `has_p203=true` → у месяцев есть `sum_p203`; если
  `has_gvs=false` → `V_gvs=0` во всех месяцах.
- Числа — сырые, без форматирования; даты в ISO.

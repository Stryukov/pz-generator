# Спецификация пояснительной записки — Тип А (v2, согласовано с экспертом)

Коммерческий абонент с НВЦС. Описание блоков для автоматической генерации.
Все открытые вопросы закрыты; решения внесены в правила блоков.

Условные обозначения:
- **[поле]** — подстановка значения.
- **Плейсхолдер** — вставляется, когда данных нет; в HTML оформляется как `<code class="ph" style="color:#c0392b">&lt;…&gt;</code>` (угловые скобки + цветной код); исполнитель
  находит все пропуски по угловым скобкам `<…>` / красному коду.
- Обяз. / Усл. — включается всегда / по флагу.

---

## Источники данных (приоритет)

1. **Расчёт (PDF, в будущем xlsx)** — основной источник чисел и флагов.
2. **Доп-контекст от исполнителя** (тело письма или вложение по шаблону) — переопределяет
   и дополняет: исполнитель, назначение, НПА, наименование/договор, режим НВЦС.
3. **Плейсхолдер** — если данных нет ни в расчёте, ни в доп-контексте.

Правило разрешения: доп-контекст > расчёт > плейсхолдер. (Наименование, договор, адрес —
из расчёта; если нет → доп-контекст; если нет → плейсхолдер.)

---

## Флаги (вычисляются на шаге извлечения, до генерации)

| Флаг | Как определяется из расчёта |
|---|---|
| `calc_method` | `pu` / `norm` — по наличию ПУ или норматива |
| `is_recalc` | повторный расчёт в связи с поверкой (признак в расчёте/доп-контексте) |
| `has_nvcs` | **есть колонка/сумма НВЦС в расчёте → true** |
| `nvcs_mode` | по умолчанию `p123_4`; `razdel_13` только если указано в доп-контексте |
| `k_coefficient` | **вычисляется: K = НВЦС_Всего ÷ стоки_с_НДС** (обычно 0,5) |
| `has_p203` | **есть колонка/сумма п. 203 в расчёте → true** |
| `has_gvs` | **есть объём стоков ГВС в расчёте → true** |
| `has_seasonality` | если `has_gvs` и объём ГВС меняется по месяцам (есть/ноль) |
| `tariff_periods` | все тарифные интервалы, встречающиеся в расчёте |

## Блок 0 — Шапка (обяз.)
- **Что:** «Пояснительная записка к расчёту суммы задолженности за услуги водопотребления
  и водоотведения по абоненту **[наименование]**.» При наличии — **[№ и дата договора]**.
- **Источник:** наименование, № и дата договора — из расчёта; нет → доп-контекст → «‹название абонента›».

## Блок 1 — Метод расчёта (обяз.)
- **Что:** по ПУ или по нормативу.
- **Правила:**
  - ПУ — **всегда таблицей** (для единообразия), даже при одном приборе. Колонки:
    № | Объект | № прибора учёта | дата поверки. Нет даты поверки → «‹дата поверки›».
  - Норматив — ссылка на приказ + объём м³/мес. НПА берётся из доп-контекста; нет →
    «‹укажите НПА по нормативу›». *(На будущее: таблица соответствия из папки нормативов
    S:\… — подбор НПА по стоимости/тарифу в расчёте. Пока не автоматизируется.)*
  - `is_recalc` → добавить «повторно в связи с поверкой».
- **Источник:** расчёт (метод, ПУ), доп-контекст (НПА).

## Блок 2 — Назначение объекта (обяз., **удаляемый исполнителем**)
- **Что:** «По адресу: **[адрес]** располагается **[назначение]**.»
- **Правила:** назначение — из договора (если приложен доп-контекстом) или из доп-контекста
  вручную; нет → формулировка с плейсхолдером `<назначение объекта>`. Несколько объектов —
  перечислить каждый. **Блок оформляется так, чтобы исполнитель мог полностью удалить его**,
  если назначение не имеет значения для данной записки.
- **Связь:** назначение = основание для блока 3 (п. 123(4)).
- **Источник:** договор / доп-контекст.

## Блок 3 — Основание НВЦС (усл.: `has_nvcs`)
- **Что:** правовое обоснование платы за негативное воздействие.
- **Вариации:**
  - `p123_4` (**по умолчанию**) — 3 абзаца-болванки (verbatim, не генерировать):
    (1) деятельность подпадает под п. 123(4) [и п. 203, если `has_p203`];
    (2) абзац про упрощённый порядок; (3) абзац про презумпцию превышения.
  - `razdel_13` — только если задано в доп-контексте; текст по разделу XIII, **без** абзацев
    про «заведомо опасную деятельность».
  - НВЦС нет → блок отсутствует (и блоки 4, 8 тоже, если п. 203 нет).
- **Источник:** факт и коэффициент — из расчёта; режим — доп-контекст (по умолчанию `p123_4`).

## Блок 4 — Загрязняющие вещества, п. 203 (усл.: `has_p203`)
- **Что:** «Согласно п. 203 Правил № 644 … Пнорм. сост. = 2 × Т × Qпр1.» (болванка verbatim).
- **Правило:** самостоятельное начисление, не часть НВЦС. Наличие — **из расчёта** (как НВЦС).
- **Источник:** расчёт.

## Блок 5 — Что входит в расчёт (обяз.)
- **Что:** «В этой связи, расчёт начисления платы содержит в себе начисления за ХВС,
  стоки ХВ[, плату за негативное воздействие…][, а также плату за сброс загрязняющих веществ].»
- **Правило:** части в скобках — по флагам `has_nvcs`, `has_p203`. Порядок фиксирован.

## Блок 6 — Тарифы (обяз.)
- **Что:** тарифы ХВС и ВО + реквизиты постановления регулятора, по всем интервалам периода.
- **Правило:** формулировку и «с НДС / без НДС» брать **как в расчёте**; итоговая сумма — с НДС.
  Подставлять **все** `tariff_periods` (1-3 интервала).
- **Источник:** расчёт; реквизиты постановления — расчёт/доп-контекст, нет → «‹НПА по тарифу›».

## Блок 7 — Расшифровка расчёта (обяз.)
- **Что:** пример помесячного расчёта + фраза «за следующие периоды — аналогично».
- **Правила (образец — как у НАТЭК):**
  - Пример по **первому месяцу**; если он «неровный» (нетипичный) — по репрезентативному.
  - Строки: ХВС → объём стоков (= потребление ХВС, + ГВС если `has_gvs`) → стоки → НВЦС
    (см. блок 8) → п. 203 (если `has_p203`) → итог за месяц.
  - **Сезонность** (`has_seasonality`): два образца — межотопительный (только стоки ХВС) и
    отопительный (стоки ХВС + ГВС). Определяется по объёму стоков ГВС: есть объём → отопит.
    сезон; ноль → ГВС идёт по трубам отопления, летом отсутствует.
  - Источник объёма ГВС в тексте **не указывается**.
  - Фраза-ссылка: «Расчёт за следующие периоды произведён аналогично **[месяц] [год]** г.»;
    при сезонности — с указанием, какие месяцы к какому образцу.
- **Источник:** расчёт.

## Блок 8 — Расшифровка НВЦС (усл.: `has_nvcs`)
- **Что:** формула и подстановка.
- **Правило (`p123_4`):** привести формулу П = К × Т × Qпр1 (болванка), затем
  **«К оплате за НВЦС: [стоки с НДС] × [K] = [сумма] руб.»**
  ⚠️ В тексте база — **стоки с НДС** (закреплено экспертом), несмотря на то что в Excel
  расчёт идёт от тарифа без НДС. Результат идентичен; в записке — формулировка от стоков с НДС.
- **Правило (`razdel_13`):** описание по разделу XIII с повышающим коэффициентом.
- **Источник:** расчёт.

## Блок 9 — Баланс и итоги (обяз.)
- **Что:** «Всего начислено: **[сумма]** руб. Оплачено: **[сумма]** руб. Остаток
  задолженности: **[начислено − оплачено]** руб.»
- **Правило:** **пени не включаются** — расчёт пени идёт отдельным документом.
- **Источник:** расчёт (Итого / Оплачено / Остаток).

## Блок 10 — Исполнитель (обяз.)
- **Что:** «Исполнитель: **[ФИО, должность]**.»
- **Правило:** НЕ «представитель по доверенности», НЕ основание подписи. Только исполнитель.
  Берётся из доп-контекста (мини-шаблон); резерв — подпись письма; нет → «‹исполнитель: ФИО, должность›».
- **Источник:** доп-контекст.

---

## Порядок сборки
`0 → 1 → 2(удаляемый) → 3(усл.) → 4(усл.) → 5 → 6 → 7 → 8(усл.) → 9 → 10`

## Изменения относительно v1 (по ответам эксперта)
- ПУ — всегда таблицей.
- `has_nvcs`, `has_p203`, `has_gvs`, `k_coefficient` — вычисляются из расчёта.
- `nvcs_mode` по умолчанию `p123_4`; `razdel_13` — только по доп-контексту.
- Тариф — как в расчёте, итог с НДС.
- Сезонность — по объёму стоков ГВС; образец как у НАТЭК; пример по первому/репрезентативному месяцу.
- НВЦС в тексте — от стоков с НДС.
- Пени в записку не входят.
- Блок 10 — исполнитель (не представитель); из доп-контекста.
- Блок 2 — удаляемый исполнителем.
- Плейсхолдеры — угловые скобки `<…>`, оформленные цветным кодом (`<code class="ph">`).

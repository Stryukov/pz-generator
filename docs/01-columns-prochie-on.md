# Карта колонок — Прочие ОН (xlsx: биллинг-выгрузка и её ручная доработка)

Подключается к контракту извлечения (`01-extraction-contract.md`) по типу расчёта.
Покрывает и старую биллинг-выгрузку (`V_RP_PKV_DBT_REP_UL_NACH_PAY-N.xlsx`), и
стандартизованный образец (`1139 ОБРАЗЕЦ Прочие ОН`) — заголовки у них совпадают.

⚠️ **Файл почти всегда доработан руками**: сотрудник выгружает расчёт из биллинга и правит его
(биллинг пока не соответствует требованиям). Поэтому колонки определять **строго по заголовкам,
НЕ по позициям** — их состав, порядок и количество плавают между файлами.

Текст приходит `;`-разделённым (по строке на ряд таблицы): шапка с реквизитами, затем
двух-трёхуровневые заголовки и строка с **нумерацией колонок** (`1`, `2`, … и формулы).

## Реквизиты — в шапке над таблицей
Название расчёта; строка «[абонент], договор № […]» → `abonent.name`, `contract_no`;
строка «за период: …». Под таблицей — блок подписи «Исполнитель:» / должность / ФИО+телефон
(см. правило `executor_context.ispolnitel` в §4 контракта).

## Колонки

| Заголовок | → манифест |
|---|---|
| «Объект водопотребления и водоотведения, адрес» | `abonent.address`; объектов может быть несколько |
| «Период задолженности» | `months[].month` |
| «Дата, № счет-фактуры» | не используется |
| «Тариф, руб/м3» → «ХВС» | `tariffs[].tariff_hvs` |
| «Тариф, руб/м3» → «Стоки ХВС, ГВС» | `tariffs[].tariff_vo` |
| «Объем потребленного ХВС, м3» → «по прибору учета» / «по нормативу» / **«Итого ХВС»** | `V_hvs` = **Итого**; метод: заполнена «по прибору учета» → `calc_method="pu"`, иначе `"norm"` |
| «Объем стоков ХВС, м3» | часть стоков |
| «Объем стоков ГВС, м3» | `V_gvs` |
| «Итого объем стоков ХВС и ГВС, м3» | `V_stoki` |
| «Сумма к оплате за ХВС (руб. с НДС)» → «по прибору учета» / «по нормативу» / **«Итого»** | `sum_hvs` = **Итого** |
| «Сумма к оплате стоки ХВС (руб. с НДС)» / «… стоки ГВС …» | слагаемые стоков |
| «Всего к оплате стоки ХВС и ГВС (руб. с НДС)» | `sum_stoki` |
| «Всего к оплате (руб. с НДС)» | `month_total` |
| «Оплачено, руб.» | оплата за месяц |
| «Дата, № п/п» | не используется |
| «Остаток задолженности, руб.» | остаток |

**Игнорировать подколонку «по прибору учета» у стоков ГВС**, если она встретилась: объём стоков
практически никогда не считается по прибору, эту колонку скрывают, и её значения в расчёт не
идут. Брать ту колонку стоков ГВС, которая участвует в «Итого объем стоков ХВС и ГВС».

## НДС
Определять по **строке нумерации колонок** (см. §2 контракта): в этом семействе формулы сумм
записаны явно — `12=6*4*1,2` означает, что **тариф без НДС** и самопроверка `×1,2` действует.
Заголовки сумм при этом всё равно гласят «руб. с НДС» — это про сумму, не про тариф.

## Служебные строки
Строки «Итого за [месяц]» и «Всего: объем / оплата / долг» — **в `months[]` не включать**.
«Всего: оплата» → `totals.paid`; «Всего: долг» → `totals.balance`;
`totals.charged` = сумма `month_total` (сверить с оплатой + долгом).

## Особые случаи
- **Сторно-месяц**: начисление по ПУ и равное отрицательное снятие по нормативу (итог месяца
  пуст/0) → в `months[]` все объёмы и суммы = 0, `note` = «перерасчёт/сторно — проверьте».
- **Нулевой ХВС при ненулевых стоках** — это **не** сторно: бывает, что потребление ХВС = 0,
  а стоки ГВС начисляются. Месяц извлекать как есть, `note` не ставить.
- **«Корректировка долга»** в колонке «Дата, № п/п» — переплата, перенесённая с прошлых
  периодов. В манифест не переносить, в записку не выводить.
- **НВЦС / п.203**: колонок нет → `has_nvcs=false`, `has_p203=false`. Они появляются, когда
  водоканал наш (тогда в расчёте есть соответствующие суммы) — правило то же, что везде:
  есть колонка → флаг `true` и сумма из неё, нет → `false`, не выдумывать.

`doc_type` для манифеста: `prochie-on`.

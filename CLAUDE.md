# CLAUDE.md — контекст проекта pz-generator

Этот файл — постоянный контекст для Claude Code. Кратко: что за проект, какие решения
приняты и почему, чтобы не переоткрывать уже закрытые вопросы.

## Что это
Автоматическая генерация пояснительных записок (ПЗ) к расчётам задолженности за
водоснабжение и водоотведение. Пайплайн: расчёт из биллинга (PDF) + доп-контекст исполнителя
(письмо) → ИИ извлекает данные → валидация → ИИ генерирует записку (DOCX). Оркестрация — n8n.
Репозиторий: https://github.com/Stryukov/pz-generator (ветка main).

## Архитектура (3 шага + почта)
1. Приём письма (триггер по тегу темы), забор вложений и тела.
2. **Извлечение** (ИИ) → манифест (JSON по делу). Контракт: docs/01, схема: docs/02.
3. **Валидация** (код в n8n) → сверка ключевых чисел. Правила: docs/03.
4. **Генерация** (ИИ) → записка + комментарии исполнителю. Структура: docs/04, контракт: docs/05.
5. Ответ на письмо с DOCX + расчётом.

Манифест (docs/02-manifest-schema.md) — общий стык: производит извлечение, читают валидация
и генерация.

## Ключевые доменные решения (закрыты с экспертом, не пересматривать без причины)
- Область — **Тип А**: коммерческий абонент с платой за негативное воздействие (НВЦС).
- **НВЦС в тексте** = стоки с НДС × K (K обычно 0,5). В Excel считается от тарифа без НДС —
  результат идентичен, но в записке формулировка от стоков с НДС.
- **K вычисляется** из расчёта (sum_nvcs / sum_stoki), не хардкодится.
- **п. 203** (загрязняющие вещества) — самостоятельное начисление, НЕ часть НВЦС.
  Может быть при отсутствующем НВЦС и наоборот (Судоверфь: НВЦС есть, п.203 нет).
- **Пени** в записку не входят — отдельный документ.
- **Подпись** — «Исполнитель: ФИО, должность», не «представитель по доверенности».
- **Сезонность** определяется по наличию объёма стоков ГВС; при ней — два образца расчёта.
- ПУ в записке — всегда таблицей (единообразие).
- Тарифы — все интервалы периода; формулировку с/без НДС брать как в расчёте, итог с НДС.

## Конвенции
- Числа: манифест хранит сырые (11273.59); форматирование (11 273,59 руб.) — только генератор.
- Плейсхолдеры — единый маркер «‹…›» (ищется по «‹»).
- Юр-болванки (3 абзаца п.123(4), формулы п.203/НВЦС) вставляются ДОСЛОВНО, ИИ их не переписывает.
- Промпты агентов простые; вся логика — в контрактах/структуре, которые флоу тянет из репо.
- **Флоу статичен**: при изменениях правим docs/*.md и схему манифеста, не сам флоу.
- Валидация — минимальная: пример-месяц + итоги (начислено/остаток). Не все месяцы.
- Расхождение валидации → повторное извлечение с ОС → если снова, поле = assumption + коммент.
- Версионирование — через git; суффиксы версий в именах файлов не используются.
- Именование латиницей: type (не tip); файлы с префиксом порядка пайплайна (00–05).

## Статус
Спека и контракты Типа А готовы. Флоу собран (n8n/). НЕ протестирован на реальном письме.
Известные места доводки: (1) узел HTML→DOCX отключён — нужен внешний конвертер; (2) разбор
вложений входящего письма может требовать подстройки под версию n8n / почтовый узел.
